## 三、根因：队尾永久饥饿

复现队列构成（本地干跑，零网络请求）：

```
universe=3472   have=2398   current=1800
① 当前成分 × 有记录（45 根）    = 1564
② 当前成分 × 无记录（3000 根）  =  236
③ 历史成分 × 无记录（3000 根）  =  838
```

**铁证**：把「升序前 801 只」与实际拿到 9-14 价格的集合比对 —— **重合 800/801（99.9%）**。

| 观察项 | 实测 |
|---|---|
| 有价代码 min / max | `000001` / **`600461`** |
| 缺价代码 min / max | **`600301`** / `689009` |
| 缺价代码在队列中的升序位次 | **742 ~ 1563**（中位 1182） |
| 缺价代码前缀分布 | 601xx 171、603xx 166、605xx 20、688xx 213、689xx 1 |

→ 队列是**固定升序**，单轮必然在限流处被截断（约 800 只），**下次又从 `000001` 开始**：
同一批队尾代码连续三轮零进展，而排在其后的两组回补（236 + 838 只）**三轮一次都没轮到**。
**限流不是唯一瓶颈，「固定队头 + 必然截断」本身就会制造永久饥饿。**

## 四、修复（`26f6abe`）

| 项 | 改动 |
|---|---|
| 队列顺序 | 四层优先：① 当前成分 × **当日缺价**(45 根) → ② 当前成分 × 无记录(3000 根) → ③ 当前成分 × **当日有价**(45 根，自愈近期缺口) → ④ 历史成分 × 无记录(3000 根) |
| 参照日 | 取自价格面板最后一行（非外部日历）；数据源当日未更新时只退化为"全都缺"，不会出错 |
| 轮转 | ① 组带游标 `output/price_cursor.json`（随提交入库），下轮从截断处接着做（取模）；②④ 组不加游标——抓成功即进 `stored_codes`、下轮自动退队，天然收敛 |
| 冷却阈值 | `COOLDOWN_DOMINANCE` 0.6 → **0.75**（配合轮转，单轮产出越多、所需轮数越少） |
| 监控 | 结构报告新增「抓取队列游标」行：连续多轮起点不动且缺口不减 = 单轮产出为 0 |
| 文档 | METHODOLOGY §2.1 新增「队列轮转（防饥饿）」+ 回归实测；量级参考按新结构重算；局限 7、README 同步 |

本地验证（拦截 `run()` 干跑）：队列 2638 = 763+236+801+838，分段正确，**当日缺价组确在队首**；
游标 0 → 800 时队首由 `600301` 变为 `600475`，轮转生效。
